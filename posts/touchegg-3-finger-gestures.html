Windows-style 3-finger gestures on Linux Mint Cinnamon

2026-08-17 · repo

Coming from Windows, the one thing I immediately missed was swiping with 3–4 fingers to switch virtual desktops. On Linux Mint Cinnamon it just doesn't exist out of the box, and the path to getting it working turned out to be full of small, mostly undocumented traps. This is the story and the working setup.

Why it doesn't work out of the box

Cinnamon's window manager (Muffin) has no native handling for multi-finger swipes. There's a gesture engine under org.cinnamon.gestures, but it's limited, disabled by default, and the actions it supports are fixed — you can't map a gesture to an arbitrary key or command. The standard solution is Touchégg, a daemon that grabs the touchpad via libinput and turns gestures into actions.

Installing Touchégg

sudo apt install touchegg
sudo systemctl disable --now touchegg
sudo usermod -a -G input "$USER"   # grant access to /dev/input/event* (needs re-login)

The second line is important. The Debian package installs a system service running as root. Root daemons ignore your ~/.config/touchegg/touchegg.conf, so gestures configured in your home dir silently never fire. The third line bit me on a clean install: input devices are owned by root:input with mode crw-rw----, and the user-level daemon can't open them without the input group. To test before re-logging in: sg input -c 'nohup /usr/bin/touchegg --daemon >/dev/null 2>&1 &'.

Trap #1: Touchégg is two processes

Here's the part that cost me the most time. Touchégg v2 is split in two:

  • touchegg --daemon — grabs the touchpad and gathers gestures, executing nothing
  • touchegg (no args) — the client: reads your config and executes the actions, talking to the daemon over D-Bus

Run only the daemon and your gestures are collected and silently dropped. Run only the client and it can't connect. Both must be running, and both must start at login:

nohup /usr/bin/touchegg --daemon >/dev/null 2>&1 &
nohup /usr/bin/touchegg >/dev/null 2>&1 &

Trap #2: EXECUTE doesn't exist in v2

Every tutorial online says to use <action type="EXECUTE"><execute>cmd</execute></action>. In Touchégg v2 the action was renamed to RUN_COMMAND with a <command> parameter. With the old syntax the client logs the wonderfully unhelpful:

Ignoring this gesture. This could mean no action is configured, the configured action is not supported…

Running the client with --debug is what exposed the real problem.

Trap #3: Expo has no keybinding

I wanted swipe-up for the Mint menu and swipe-down for the workspace view (Expo). But Cinnamon's Expo — the all-workspaces overview — has no keyboard shortcut at all; it's only reachable via the hot corner. Touchégg can only send keys or run commands. The workaround: Cinnamon exposes a JS eval over D-Bus, and imports.ui.main.expo.toggle() exists in its UI namespace:

gdbus call --session --dest org.Cinnamon --object-path /org/Cinnamon \
  --method org.Cinnamon.Eval "imports.ui.main.expo.toggle()"

The final config

GestureAction
3-finger swipe UPMint menu (Super)
3-finger swipe DOWNExpo — workspace view via D-Bus eval
3-finger swipe LEFTNext workspace
3-finger swipe RIGHTPrevious workspace
 
<touchégg>
  <settings>
    <property name="animation_delay">150</property>
    <property name="action_execute_threshold">20</property>
  </settings>
  <application name="All">
    <gesture type="SWIPE" fingers="3" direction="UP">
      <action type="SEND_KEYS">
        <modifiers>Super_L</modifiers>
        <keys></keys>
      </action>
    </gesture>
    <gesture type="SWIPE" fingers="3" direction="DOWN">
      <action type="RUN_COMMAND">
        <command>sh -c 'gdbus call --session --dest org.Cinnamon --object-path /org/Cinnamon --method org.Cinnamon.Eval "imports.ui.main.expo.toggle()"'</command>
      </action>
    </gesture>
    <gesture type="SWIPE" fingers="3" direction="LEFT">
      <action type="SEND_KEYS">
        <modifiers>Control_L+Alt_L</modifiers>
        <keys>Right</keys>
      </action>
    </gesture>
    <gesture type="SWIPE" fingers="3" direction="RIGHT">
      <action type="SEND_KEYS">
        <modifiers>Control_L+Alt_L</modifiers>
        <keys>Left</keys>
      </action>
    </gesture>
  </application>
</touchégg>

Summary

Three traps, three fixes: kill the root daemon, run both processes, use RUN_COMMAND — and don't forget the input group. Everything else — the workspace keybindings, the Expo eval — is Cinnamon specifics. The full portable setup (config + README) is on GitHub, so I never have to debug this again on the next machine.
